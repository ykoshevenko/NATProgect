# NATProject

**Анонимный офлайн-мессенджер** — без аккаунтов, без интернета, без центральных серверов.

## Статус

⚠️ Проект находится в активной разработке. Реализовано ядро и базовая модель комнат; сеть и UI — впереди.

## Что работает сейчас

- **Генерация личности** — при первом запуске устройство создаёт уникальную пару X25519-ключей и случайный ник. Аккаунтов нет, регистрация не нужна.
- **E2EE** — два участника могут сами согласовать общий ключ и шифровать сообщения (ChaCha20-Poly1305). Подделка или подмен ciphertext обнаруживаются.
- **Проверка собеседника** — до начала общения стороны сверяют отпечаток ключа (по QR или вслепую), чтобы убедиться, что разговор идёт с нужным человеком.
- **Комнаты (NAT-соединения)** — любой участник может создать сеть с коротким invite-кодом (например, «АБ-CD-EF») и присоединить к ней других. Все участники оказываются в одной локальной сети.
- **Управление участниками** — добавление, удаление, поиск по ключу, список участников.
- **Тесты** — 14 юнит-тестов покрывают криптографию, комнаты и проверку целостности.

## Принцип работы (кратко)

1. **Кто ты** — твой «паспорт» в мессенджере — это пара математических ключей и случайный ник. Ник не является идентификатором, он лишь ярлык для интерфейса. Настоящее узнавание — по публичному ключу.
2. **Как шифруется** — два человека обмениваются публичными ключами и по формуле ECDH получают одинаковый общий секрет. Из него выводится ключ для ChaCha20-Poly1305. Шифрование и проверка подлинности идут вместе — если хоть один байт сообщения или доп. данных (`aad`) изменился, расшифровка откажет.
3. **Как создаётся комната** — участник генерирует случайную «соль» и превращает её в короткий код (base32). Показывает код остальным. Кто ввёл тот же код — оказался в его сети. Хост анонсируется по локальной сети, остальные подключаются и начинают обмениваться ключами.
4. **Откуда берётся уверенность** — всё проверяется автоматически: ECDH-симметрия (оба получают один ключ), tampering detection (подмена не проходит), верификация invite-кода, отсутствие дубликатов участников.

## Архитектура (ядро на Rust)

- `core/src/error.rs` — тип ошибок ядра;
- `core/src/identity.rs` — личность устройства (ключи + ник);
- `core/src/crypto.rs` — ECDH + HKDF + ChaCha20-Poly1305;
- `core/src/network.rs` — модель комнаты, invite-код, участники;
- `core/src/discovery.rs` — поиск соседей по UDP (в разработке);
- `core/src/transport.rs` — TCP-соединения между узлами (в разработке);
- `core/src/router.rs` — маршрутизация по мешу (в разработке);
- `app/` — клиент на Flutter + Rust-ядро через FFI (в разработке).
